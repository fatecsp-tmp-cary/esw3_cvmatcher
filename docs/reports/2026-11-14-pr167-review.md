## Integration requirements and limits

PR #168 modifies the same ingestion loop. Preserve buffering and ordered bounded
locking when integrating it. Its final snapshot-attestation health/count requests
must also complete before identity locks are acquired; qualification must still
include final persistence rejection counts. Later absence/lifecycle writes must
obey the same lock order. Worker source scheduling remains separate scope.

Buffering retains normalized job observations until the bounded scan finishes,
trading memory for no remote waits under identity locks and all-or-nothing scan
writes. A large batch can occupy every stripe and serialize unrelated writers;
this does not assert a throughput or fairness guarantee. Existing rolling
processes using the previous lock namespace must be stopped before deploying the
new coordination scheme. No per-record commits, migrations, lifecycle-policy or
product-scope changes are introduced.
